# First launch implementation

Approved reference: `concept-board-v3.png`. Mode: Operate. Existing Cuekeeper
Daybook/Combined Glass identity, exact cue-card paths, semantic SF typography,
ivory/forest light appearance and charcoal/mint dark appearance.

## Direction contract

THESIS: One brief welcome, useful defaults, optional Calendar, then the daybook.
Sync starts automatically; backup recovery remains a secondary, explicit action.

OWN-WORLD: The existing cue-card mark and native controls carry the identity.
No new visual system, decorative assets, sample records, or mandatory account setup.

STORY: A new installation configures currency, role, home timezone and appearance.
Existing installations go directly to their daybook. Settings can replay setup.
Records arriving during setup change the welcome to a returning-user state.

FIRST VIEWPORT: Centered brand and welcome, live iCloud status, primary Get started
or Continue setup, secondary Recover from a backup. No removed marketing paragraph.
Preferences, Calendar and recovery preserve the approved reduced copy.

FORM: Native NavigationStack, grouped preference rows, bottom safe-area actions on
iPhone and a compact native form sheet on iPad. Setup subpages reuse the app's
brand lockup in the native navigation bar and its existing 20-point page margins.
Native back controls and glass rendering are authoritative.
At accessibility sizes, content scrolls and Appearance becomes a native menu.
The user explicitly approved the menu adaptation and existing iPad sidebar.
After reviewing the first real screenshots, the user found the implementation
bland and too empty. They explicitly selected bottom actions on iPhone with compact
setup on iPad. This tighter composition supersedes the earlier full-screen iPad
interpretation of the board, without adding any of the removed helper text.

## Confirmed behavior

- Currency and role prefill new entries. Existing client currency defaults retain
  their established precedence. Home timezone seeds the secondary local-time view
  for new remote/hybrid work; event/session timezones remain independent.
- Preferences are device-local, editable in Settings. Appearance applies immediately.
  No currency conversion or changes to existing events occur.
- Existing store detection skips setup on upgrade. New installs save completion
  after Calendar is connected or skipped. Incomplete setup can resume on relaunch.
- The Calendar connection screen reuses the existing permission and ownership flow.
- Backup selection invokes the existing merge restore after a native confirmation.
  The selection screen omits the helper text removed by the user; confirmation
  retains the actual effects of restoration. No backup creation/deletion in setup.
- An empty daybook hides search, filters and routine iCloud feedback. Offline/error
  feedback remains available. iPad retains its sidebar and uses two columns while empty.

## Truthful states and limitations

No empty-cloud assertion is made: local emptiness and an import completion do not
prove the account has no data. Syncing your data is shown only during an import.
Actual offline and account failures replace the normal status. Backup loading,
empty, error, account-change and cancellation states are handled separately.

Native screenshots are generated by terminal-driven Xcode tests, never browser or
computer-control tools. Simulated sync states do not prove physical-device delivery.
No schema change, deployment, archive upload or TestFlight release is in scope.
